## Funding facts and limits

On the sampled mainnet fee of 100 MON-gwei base / 102 MON-gwei gas price, the four-contract dry run reserved 7,217,323 gas and estimated **0.736166946 MON** deployment cost. The S1 wallet `0x8cf8d07115760a5D4Db4a6561729E8ed4de4D8CA` had **0 mainnet MON** and initially **9.04256862 testnet MON**. An external 10 testMON top-up was then observed; the successful four-contract testnet deployment charged **0.736169598 testMON**. See `docs/verification/testnet-deployment.json` for actual receipts. Mainnet is optional for hackathon eligibility and has not been deployed. Recheck before sending. Exact calldata and constructor arguments are in ignored `deployments/plans/143.json`.

Funding-plan campaign variables are planning inputs, not enforced runtime caps. Default tooling remains three bursts / 600 awake seconds; a controlled one-burst / 120-second example uses `RECORDING_BURSTS=1`, `RECORDING_AWAKE_SECONDS=120`, `RECORDING_AWAKE_SESSIONS=1`, `RECORDING_BLOCK_INTERVAL_MS=300`. This exceeds the minimum 96-second wake/burst window with Mo's default 90-second timeout. Each extra visit/order/wake can extend runtime activity; monitor and stop it deliberately. Faster blocks, fee changes, failed sends, backlog or extra traffic require another plan.

The conservative example includes full gas-cap reservations for Pete, Mo and keeper claims/cranks even though placements normally self-clear. It is not a required actual expense or an unlimited judge-traffic budget. Per-key retained reserves, deployment, faucet seeding and relayer traffic are additional. Use the planner's actual public wallet addresses; never put private keys in chat or PUBLIC settings.
