# Metropolis submission requirements

Source: Rules & Guidelines v3.0, updated 3 September 2026, and dashboard text copied by Rahul directly from his registered account. This is a compliance checklist, not acceptance of terms or a completed submission.

## Mandatory evidence

| Requirement | Batchelor status |
|---|---|
| Working product deployed on Monad mainnet **or testnet** (§4.1, §9.2) | Four contracts deployed and checked on testnet; hosted web/bots/indexer and complete judge flow pending. Mainnet is optional for eligibility. |
| Public GitHub complete source and OSI-approved license (§4.1, §7.2) | Public repository, MIT project license, S1–S8 branch pushed. Final release fixes still require the requested push choice. |
| Runnable README, architecture/stack and deployment instructions (§4.1, §9.1) | README, design, Monad explanation and deployment guides prepared. |
| External dependency attribution and AI disclosure in README (§4.1) | Present; no independent human review is claimed. |
| Substantial majority built during the window and build history (§4.1) | Preserved local/GitHub history; do not squash or claim unbuilt features. |
| Public video ≤3 minutes showing actual operation and Monad interactions (§4.1, §9.4) | Script prepared; actual hosted recording/upload pending. |
| Contract addresses or transaction hashes and explanation of why Monad (§9.2) | Testnet addresses/receipts and same-bytecode benchmark explanation available. |
| One project and one track; team 1–5, designated contact (§2.4–2.5) | Intended track: Onchain Finance & Trading. Dashboard showed profile/team complete, project/tracks/submission incomplete. Participant confirms eligibility. |
| Submit on the hackathon website before its recorded deadline (§4.2) | Dashboard: **14 October 2026, 09:29 GMT+5:30**. Rules: 13 October, 23:59 ET; these denote the same deadline. Submission has not occurred. |
| Sponsor-specific requirements if entering a bounty (§3.3) | Current Mera/Envio bounty text still needs confirmation; do not claim eligibility solely from the build pack. |

The Rules require open source, overriding the marketing FAQ's softer wording. A custom domain, paid RPC subscription, every sponsor voucher, native mobile app, new token launch and mainnet deployment are not universal requirements in the supplied rules.

The dashboard and rules differ on judging/winner dates. This does not change the consistent submission cutoff above; use the actual dashboard for later schedule updates. No bot activity is presented as organic adoption or real-value volume. Demo tokens have no value and bots must remain clearly labelled; do not make price-manipulation or market-performance claims (§8.2, §10.4).

Final operational order: funded live services → physical-device test → actual ≤3-minute public demo → complete project profile/track → verify submitted confirmation. [Release checklist](RELEASE_CHECKLIST.md), [demo](DEMO.md), [submission copy](SUBMISSION.md).
